## 做完的四件事

### 1. 机器人牌数值逐张核对（`0ba3286`）

`tests/defect_card_values_test.cpp`（CTest `defect_card_values`）表驱动覆盖 76 张牌的基础与升级两种
形态。数值依据是游戏字节码，不是 `sts_cards.json`：那个文件只有最终数字，没有决定数字何时生效的分支。

审计过程查出 `BULLSEYE` 一处真错（漏了 8/11 点伤害，Lock-On 层数少 1），已在 `d450b8f` 修掉；其余
75 张与字节码一致。防漏口径用「`DefectCards.cpp` 里有 `case CardId::` 的牌」+ 共享 switch 的
`STRIKE_BLUE`/`DEFEND_BLUE`，不用 `cardColors == BLUE`——那张表把 `BUFFER`/`COMPILE_DRIVER` 标成了
PURPLE，把 `BRILLIANCE`/`COLLECT` 标成了 BLUE（不影响战斗，只影响变化牌池，本步不动）。

### 2. 机器人专属遗物（`402128e`）

8 个遗物逐个对字节码。只有 `INSERTER` 是错的：原实现 `counter == -1 ? 0 : 1` 让首次触发早一回合。
修成按原版「-1 → +2 归零 → 下回合 +1 到 2 才加槽」。其余 7 个（Data Disk / Emotion Chip / Frozen
Core / Cables / Nuclear Battery / Runic Capacitor / Symbiotic Virus）一致，各补了 CTest。

药水全部核对无误（Focus 2/4、Capacity 2/4、Essence of Darkness 每栏 1 颗 Dark 圣树皮 2），没改。

### 3. 遗物覆盖判据收紧（`8105e3c`）

`tools/coverage_manifest.py` 新增 `class_relic_tests` 段：遗物要在**源码有钩子**且**某个已注册的
CTest 里出现过**才算覆盖。以前只要名字出现在 `src/combat` 或 `include/combat` 就算——Inserter 就是
这么被漏掉的。补了 Cracked Core 的断言（唯一缺测试的 Defect 遗物）。

**这一项在 `--check` 里只报告不判失败**：它衡量的是「测得多好」不是「算得对不对」，而且拿铁甲战士
那 7 个未测遗物去卡机器人的检查会挡住不碰它们的改动。DEFECT 现在 9/9 全有测试，IRONCLAD 4/11。

### 4. `character_dispatch_test.cpp` 按「已全部实现」改写（`b6c0587`）

这个测试守两件事：未实现的牌打出去必须报 `unimplemented card`（不能静默跳过），已实现的牌必须正常
执行。上游用 `{DEFECT, ZAP}` 和 `{DEFECT, BALL_LIGHTNING}` 当「未实现样本」，现在两张都实现了，原断言
不可能成立。

CONTRIBUTING 要求换成同职业同类型的另一张未实现牌——**没有可换的**：机器人 71 张奖励牌 + 4 张起始牌
全部实现，jar `cards/blue/` 76 个类里唯一没有引擎 case 的 `Impulse` 是未使用类、不在 `cardStringIds`。

改法：拆成两组。`unimplemented[]` 留静默三张 + 观者三张（攻击/技能/能力各一）；`implemented[]` 放
机器人三张（Ball Lightning 攻击 / Zap 技能 / Defragment 能力），断言不报该错。三种类型在两组里都覆盖。

顺带纠正上游的一处注释错误：上游把 Zap 标成 attack、Ball Lightning 标成 skill，字节码里正好相反。

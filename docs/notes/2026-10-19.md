## 真值引擎启动链路：三关已通，只剩"必弹窗口"（17:15）
隔离环境 /e/tmp/sts-truth（desktop-1.0.jar + ModTheSpire.jar + mods/seedsearch.jar + jre 联接 + searchConfig.json），用**游戏自带 JRE 1.8.0_144** 启动：
`./jre/bin/java.exe -jar ModTheSpire.jar --mods seedsearch`

三关及解法（全部来自 MTS 官方源码，未造轮子）：
1. **NPE（ProcessBuilder.start）** — 根因不是"Steam 检测 NPE"：`SteamSearch.getSteamPath()` 在 Windows 上**只读** `%ProgramFiles%(x86)\Steam\steamapps` / `%ProgramFiles%\Steam\steamapps` 两个硬编码路径（**不读注册表**）；用户 Steam 装在 `D:\games\steam`、游戏在 `E:\SteamLibrary` → 都找不到 → `installDir=null` → `findJRE()` 返回 null → ProcessBuilder 数组含 null → NPE
   - 解法：`findJRE()` 第一段优先查**本地** `jre/bin/java.exe`，命中就不走 Steam → 在工作目录建 `jre` 目录联接指向游戏自带 jre（`cmd //c mklink /J jre <目标>`）
   - 补充：`desktop-1.0.jar` 放当前目录时 Loader 不需要 Steam 找 jar（源码里有该分支）
2. **`Unable to find Mod ID 'seedsearch'`** — ModTheSpire.json 的字段名是 **`modid`** 不是 `id`（官方 resources/ModTheSpire.json 用的 modid）
3. **Java 25 → `NoSuchFieldException: packages`** — MTS 3.30.3 的 MTSClassLoader 反射 `ClassLoader.packages`，Java 9+ 已移除 → 必须用 **Java 8**。本机可用：游戏自带 jre（1.8.0_144）+ jdk11/17/25。SeedSearch 的 class 已是 major 52（Java 8）无需重编
4. **`NoClassDefFoundError: org/mockito/Mockito`** — SeedSearch 用 mockito mock 图形；项目用 maven-shade 打 fat jar，本机无 maven → 手工从 Maven Central 下 mockito-core 2.28.2 + byte-buddy 1.9.10 + byte-buddy-agent 1.9.10 + objenesis 2.6，解压合并进 seedsearch.jar

**当前卡点（非技术）**：MTS 的 `ModSelectWindow` 构造函数不 setVisible，但 `Loader.main` 会无条件 `ex.setVisible(true)`；skipLauncher 只是把内容换成日志面板后 `playBtn.doClick()` → **窗口一定会显示**。`-Djava.awt.headless=true` 会让 ModSelectWindow 构造抛 HeadlessException（AWT 线程死、主流程不执行，exit=0 但什么都没做）→ 不能用
→ 唯一干净路径：自写启动器直接调 `Loader.runMods(File[])` 绕过 GUI（需先补齐 POOL/MTS_VERSION 等静态初始化）。**用户上班期间禁止弹任何游戏/Mod 窗口**，改为等他方便时再跑
